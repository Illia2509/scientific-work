# Політика безпеки

## Підтримувані версії

| Версія | Підтримка |
| --- | --- |
| Гілка `main` | ✅ |
| Інші гілки й теги | ❌ |

## Як повідомити про вразливість

Не створюйте публічний issue для вразливостей.
Скористайтеся приватним повідомленням: вкладка **Security → Report a vulnerability** у цьому репозиторії.

Укажіть у повідомленні:
- опис вразливості та її можливий вплив;
- кроки для відтворення;
- версію (коміт) і середовище.

Відповідь — протягом 7 днів. Після виправлення вразливість буде описано в історії змін.

## Дані та секрети

- Репозиторій містить лише **синтетичні** дані (Synthea); реальних персональних і медичних даних немає.
- Секрети (`SECRET_KEY`, `DB_PASSWORD`) зберігаються тільки у файлі `.env`, який не потрапляє в Git; у репозиторії є лише шаблон `.env.example`.
- Історія репозиторію перевіряється на витік секретів інструментом `gitleaks`.

## Принципи безпеки системи

- Доступ до ЕМК надається лише за рішенням сервісу авторизації (RBAC + ABAC, пріоритет правил заборони).
- За недоступності сервісу авторизації доступ відхиляється (fail-closed).
- Кожна спроба доступу фіксується в журналі аудиту.
